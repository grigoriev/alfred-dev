# Карта репозитория

Эта страница объясняет, где лежит каждая подсистема плагина и какой документ читать, чтобы её понять. Цель: сократить время на ориентирование, сразу открыть нужный каталог и не потеряться между промптами, ядром на Python, хуками, памятью, визуальными скриптами и тестами.

Ветка `main`, описанная здесь, относится к плагину. Публичный лендинг живёт в ветке `Alfred-Astro` и не входит в эту карту, кроме случаев, когда релиз требует согласовать содержимое обеих веток.

---

## Общий вид

| Путь | Что содержит | Состояние документации |
|---|---|---|
| `agents/` | Промпты 10 опубликованных агентов | Хорошо описаны в `docs/agents/` |
| `commands/` | Slash-команды плагина | Теперь описаны в [commands.md](commands.md) |
| `core/` | Runtime на Python: оркестрация, память, конфигурация, Designer | Описано по темам; не хватает страниц по подсистемам |
| `hooks/` | Хуки жизненного цикла и guards | Описаны в `hooks.md` |
| `mcp/` | MCP-сервер памяти | Покрытие недостаточное |
| `skills/` | Каталог из 11 плоских skills | Описан в `skills.md` |
| `tests/` | Набор тестов и контрактов | Описан в `testing.md`, есть что улучшить |
| `visual/` | Визуальные скрипты Designer и локальный сервер | Описаны в [visual.md](visual.md) |
| `templates/` | Шаблоны артефактов и вывода | Нет своей страницы |
| `.github/workflows/` | Автоматизация CI/релиза | Нет своей страницы |

## Ключевые каталоги

### `agents/`

Здесь лежат исходные промпты, которые Claude Code находит в каталоге `agents/`. 10 опубликованных агентов лежат в `agents/*.md`; единственный опциональный агент: CTO. Разница описана в их карточках и в движке личности, а не через подкаталог `agents/optional/`.

Документация для людей лежит в `docs/agents/`. Если ты меняешь исходный агент, проверь его карточку в `docs/agents/` и все упоминания в `docs/README.md`, `docs/personality.md` и `docs/flows.md`.

### `commands/`

Содержит промпты всех slash-команд. Типы такие:

- команды процессов, например `feature.md`, `fix.md`, `ship.md`;
- опубликованные операционные команды, например `progress.md`, `retomar.md`, `memory-ui.md`;
- внутренние неопубликованные хелперы: `next.md`, `search.md`, `_composicion.md`, `_docs_vivas.md`.

Если релиз добавляет или удаляет команду, нужно согласовать четыре поверхности:

1. `commands/`;
2. `.claude-plugin/plugin.json`;
3. `README.md`;
4. `docs/commands.md`.

### `core/`

Основная исполняемая логика плагина. Самые важные модули сейчас:

- `orchestrator.py`: процессы, фазы, gates и сохранение сессии;
- `config_loader.py`: определение стека, загрузка конфигурации и подсказки;
- `personality.py`: каталог личностей и метаданные агентов;
- `memory.py`, `memory_sync.py`, `memory_ui_server.py`: постоянная память, нативная синхронизация и UI;
- `optional_agents.py`: динамический состав команды;
- `designer_*`: визуальный runtime Designer.

Основная техническая ценность плагина находится здесь, но `docs/` пока описывает её скорее по функциональным темам, чем картой модулей.

### `hooks/`

Здесь лежат скрипты, подключённые к жизненному циклу Claude Code. Каноничный манифест: `hooks/hooks.json`. Хуки обеспечивают безопасность, непрерывность, сбор активности, quality gates и память.

Когда меняешь хук, проверь:

1. `hooks/hooks.json`;
2. реализацию скрипта;
3. его тесты;
4. `docs/hooks.md`, если меняется наблюдаемое поведение.

### `mcp/`

Содержит локальный MCP-сервер памяти (`memory_server.py`). Память уже описана концептуально, но этот слой заслуживает отдельной страницы, потому что это граница интеграции с внешними инструментами.

### `visual/`

Скрипты и хелперы визуального companion Designer. Здесь лежат локальный сервер, HTML-шаблоны и генераторы экранов и вариантов. Техническая справка: [visual.md](visual.md).

### `tests/`

Набор тестов включает:

- unit-тесты ядра;
- контрактные тесты промптов и публичной поверхности;
- тесты хуков;
- тесты памяти, UI и сервера;
- тесты визуальных хелперов.

Документация по тестированию существовала, но её нужно было привести в соответствие с этим реальным покрытием.

## Как ориентироваться под задачу

| Если будешь менять... | Начни с... | Потом проверь... |
|---|---|---|
| Процесс | `commands/*.md` | `core/orchestrator.py`, `docs/flows.md` |
| Агента | `agents/*.md` | `docs/agents/`, `core/personality.py` |
| Конфигурацию | `core/config_loader.py` | `docs/configuration.md` |
| Память | `core/memory.py` | `core/memory_sync.py`, `mcp/memory_server.py`, `docs/memory.md` |
| Хуки | `hooks/hooks.json` | конкретный скрипт, его тесты и `docs/hooks.md` |
| Designer | `core/designer_*` и `visual/scripts/` | `agents/designer.md`, `docs/agents/designer.md`, `docs/visual.md` |
| Тесты/контракты | `tests/` | `docs/testing.md` |

## Расхождения документации, за которыми надо следить

В этом репозитории четыре зоны с повышенным риском drift:

- **публичные счётчики**: число команд, агентов, skills, хуков;
- **опубликованная поверхность**: `.claude-plugin/plugin.json` и маркетплейс;
- **версионирование**: README, docs, установщики, тесты согласованности;
- **операционные промпты**: commands и agents, которые быстро меняются.

Когда релиз затрагивает любую из этих зон, `docs/` нужно проверить в том же PR.
