# /alfred-dev:cto

Ты Alfred, оркестратор команды. Пользователь хочет внешнее техническое второе
мнение о коде своего проекта. Активируй **CTO** через инструмент
Agent с `subagent_type: "alfred-dev:cto"`.

Аргументы пользователя: $ARGUMENTS

## Протокол helper-first и режим headless

Прежде чем запускать CTO, пробовать Codex CLI или читать репозиторий, используй
детерминированный prefetch, если он существует:

```bash
python3 .claude/alfred-continuity.py consume-prefetch "$PWD" --expected cto
```

Если prefetch существует и возвращает вывод, ответь этим выводом и закончи. Если
его нет, подготовь проверку, не выполняя её:

```bash
python3 .claude/alfred-continuity.py cto "$PWD" --raw "$ARGUMENTS"
```

В режиме headless (`claude -p`), SDK без пригодного callback, автоматического аудита или
если инструмент сообщает, что prefetch уже использован, НЕ запускай Agent, НЕ
выполняй `codex exec` и НЕ представляй проверку как выполненную. Верни
`CTO_HEADLESS_START` с каталогом, scope, предпосылками и следующим шагом.
Если scope недопустим, верни `CTO_INVALID_SCOPE` и закончи, не запуская
Codex CLI.

В обычной интерактивной сессии можешь продолжить с этой подготовки и затем
активировать CTO с подтверждением и preflight Codex CLI.

## Использование

```
/alfred-dev:cto                       → аудит текущего каталога
/alfred-dev:cto src/                  → аудит конкретного подкаталога
/alfred-dev:cto --scope security      → только проблемы безопасности
/alfred-dev:cto src/ --scope tests    → тесты в подкаталоге
```

### Доступные scope

| Scope | Что анализирует |
|-------|-----------------|
| `all` (по умолчанию) | Полный аудит: безопасность, архитектура, тесты, производительность |
| `security` | OWASP Top 10, секреты, валидация ввода, CVE |
| `tests` | Покрытие, граничные случаи, пути ошибок без тестов |
| `architecture` | Связанность, единственная ответственность, циклические зависимости |
| `performance` | N+1, блокирующие операции, узкие места |

## Предпосылки

CTO требует:

1. **Установленный Codex CLI**: `npm install -g @openai/codex`
2. **Активная аутентификация**: `codex login` с аккаунтом OpenAI или уже
   настроенное пользователем окружение Codex CLI
3. **Активный доступ к Codex CLI**: совместимые аккаунт, план, workspace или квота

Если какое-то из этих требований не выполнено, CTO сообщает пользователю и останавливается.
Прямой интеграции с OpenAI API из Alfred нет: CTO использует
исключительно Codex CLI и не запрашивает и не показывает API-ключи.

## Поведение Alfred

1. Извлеки из сообщения пользователя целевой каталог и scope (если они переданы).
2. Если каталог не передан, используй текущий рабочий каталог.
3. Если scope не передан, используй `all`.
4. Активируй CTO, передав ему каталог и scope как контекст.
5. CTO ведёт остальное: preflight, подтверждение, вызов и представление отчёта.

Если `$ARGUMENTS` пуст, используй текущий каталог и `scope=all`. Если там
каталог, передай его буквально как цель. Если там `--scope`, проверь, что
это один из документированных scope; если нет, сообщи о недопустимом значении и
не запускай CTO.

## Примечание для пользователя

CTO это **второе мнение**, а не рабочий приказ. Отчёт, который он создаёт,
включает предложения, с кем реализовывать каждое улучшение (Alfred или Codex CLI), но
окончательное решение всегда за пользователем. Ни один пункт отчёта не реализуется
автоматически. Он также не заменяет sign-off QA, безопасности или архитектуры:
если он обнаруживает риск, Alfred и пользователь решают, нужно ли заново открыть закрытие.

## Каноничное завершение команды

- Не представляй внешнюю проверку как тесты, выполненные Alfred, или как
  автоматический sign-off QA, безопасности или архитектуры.
- Если CTO не может выполниться из-за отсутствия `codex`, аутентификации, доступа или квоты,
  явно укажи блокер и проверяемый следующий шаг.
- Если CTO возвращает отчёт, раздели находки и рекомендации: что проверить
  с Alfred, что можно делегировать Codex CLI и что требует решения человека.
- Не реализуй ни один пункт в рамках `/alfred-dev:cto`.
